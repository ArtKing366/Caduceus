# Caduceus — идея проекта

> Внутренний документ с концепцией. Файл добавлен в `.gitignore` по требованию команды и не должен публиковаться в репозитории.

## Концепция

Caduceus — интеллектуальный помощник по питанию. Первая версия — веб-приложение. В будущем на основе backend/API можно создать мобильный клиент.

Приложение объединяет дневник питания, каталог ресторанных блюд, генерацию домашних рецептов, подбор продуктов по бюджету, расчёт стоимости и списки покупок.

## Основные модули

### 1. Food Tracker
- Добавление съеденных блюд и количества порций.
- Расчёт/отображение калорий, белков, жиров и углеводов.
- Дневная статистика и история питания.
- Добавление еды по фотографии через AI с обязательной возможностью проверить и исправить распознанный результат.

### 2. Restaurant Explorer & Recipe Builder
- Поиск блюд в собственном демонстрационном каталоге ресторанов.
- Просмотр информации о блюде.
- Генерация домашнего рецепта через OpenAI API.
- Ингредиенты, количества, шаги приготовления, время и пищевая ценность.
- Замена ингредиентов и выбор режима Budget / Standard / Premium.
- Расчёт стоимости использованного количества ингредиентов отдельно от суммы покупки целых упаковок.
- Сравнение демонстрационных цен в магазинах.
- Создание списка покупок.

### 3. Dietary Preferences
- Предпочтения и фильтры: Vegan, Gluten-free, Dairy-free, Nut-free, High-protein, Budget-friendly, Low prep time.
- Учет ограничений при поиске, генерации рецептов и выборе замен.
- Строгая проверка аллергенов: неизвестный состав нельзя считать безопасным; при недостатке информации требуется предупреждение/блокировка автоматического одобрения.

### 4. Пользовательский профиль
- Регистрация и авторизация.
- JWT.
- Личные настройки и пищевые ограничения.
- Сохранённые рецепты, дневник питания и списки покупок.
- Проверка доступа к личным данным.

## Данные

Нет доступа к реальным базам продуктов, магазинов, ресторанов и их API. Поэтому создаётся собственная PostgreSQL-база с демонстрационными данными: рестораны и блюда, ингредиенты, продукты, пищевая ценность, магазины, упаковки и цены. Расчёты и бизнес-логика должны быть настоящими, но цены и каталоги не выдаются за актуальные реальные данные.

## AI
- OpenAI API для генерации домашних рецептов.
- Предложения по замене ингредиентов.
- Анализ фотографий еды с последующим подтверждением/редактированием пользователем.
- AI не является источником истины для цен и безопасности аллергенов: backend проверяет структурированные данные и выполняет расчёты.

## Стек
- Python 3.12, FastAPI, Pydantic v2.
- PostgreSQL, SQLAlchemy, Alembic.
- JWT, Pytest, Git, Docker Compose.
- OpenAI API.
- Redis и Celery по необходимости.
- pgvector/RAG — при реализации семантического поиска.
- React + TypeScript как рекомендуемый frontend первой веб-версии.
- GitHub Actions, Nginx/SSL и AWS — по выбранному варианту деплоя.

## Главный пользовательский сценарий
1. Пользователь ищет ресторанное блюдо в каталоге.
2. Получает домашний рецепт.
3. Выбирает ингредиенты и бюджетный режим.
4. Проверяет диетические ограничения.
5. Смотрит пищевую ценность и стоимость рецепта.
6. Получает список покупок и сравнение демонстрационных цен.
7. После приготовления добавляет порцию в Food Tracker.
