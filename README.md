# Caduceus — план разработки и запуск

Интеллектуальный помощник по питанию. Первая версия — веб-приложение; мобильный клиент можно добавить позднее.

> Полная концепция проекта хранится отдельно в `PROJECT_IDEA.md`. Этот файл намеренно добавлен в `.gitignore` и не попадёт в Git.

## 1. Технологический стек

- Python 3.12
- FastAPI, Pydantic v2
- PostgreSQL, SQLAlchemy 2, Alembic
- JWT-аутентификация
- OpenAI API: генерация рецептов, замены ингредиентов, анализ фотографий
- Pytest
- Docker Compose
- Redis и Celery — для кэширования и фоновых задач, когда они понадобятся
- pgvector/RAG — отдельный этап, если понадобится семантический поиск

## 2. Этапы разработки

### Этап 1. Подготовить окружение
1. Установить Python 3.12, Git и Docker Desktop.
2. Создать виртуальное окружение.
3. Установить зависимости из `requirements.txt`.
4. Создать `.env` на основе `.env.example`.
5. Проверить, что приложение запускается локально.

### Этап 2. Поднять инфраструктуру
1. Запустить PostgreSQL и Redis через Docker Compose.
2. Проверить подключение к PostgreSQL.
3. Настроить SQLAlchemy и Alembic.
4. Выполнить первую миграцию.

### Этап 3. Спроектировать и заполнить демонстрационную базу данных
Поскольку доступ к реальным каталогам и API магазинов/ресторанов отсутствует, используем собственные тестовые данные.

Предварительные сущности:
- пользователи и профили;
- диетические предпочтения и ограничения;
- рестораны и ресторанные блюда;
- ингредиенты и их пищевая ценность;
- домашние рецепты и ингредиенты рецептов;
- магазины;
- товары и размеры упаковок;
- цены товаров в магазинах;
- дневник питания и записи приёмов пищи;
- списки покупок и позиции списка.

Шаги:
1. Уточнить поля и связи каждой сущности.
2. Создать SQLAlchemy-модели.
3. Создать Alembic-миграции.
4. Подготовить seed-данные: несколько ресторанов и блюд, ингредиенты, продукты, магазины и демонстрационные цены.
5. Добавить команду/скрипт для безопасного заполнения тестовых данных.
6. Проверить расчёты на тестовых примерах.

### Этап 4. Реализовать backend по модулям
1. Регистрация, вход, JWT и профиль пользователя.
2. Каталог ресторанов и блюд.
3. Создание и сохранение домашних рецептов.
4. Ингредиенты, замены и проверка диетических ограничений.
5. Расчёт пищевой ценности рецепта и порции.
6. Расчёт стоимости использованного количества ингредиента и стоимости целых упаковок.
7. Каталог магазинов и товаров, сравнение демонстрационных цен.
8. Формирование и редактирование списков покупок.
9. Food Tracker: добавление еды, дневная статистика и история.
10. AI-интеграции: генерация рецептов, предложения замен и анализ фотографий.
11. Обработка ошибок, права доступа и валидация входных/AI-данных.

### Этап 5. Сделать визуальную часть (веб-интерфейс)
Рекомендуемый вариант — React + TypeScript, отдельный frontend, который обращается к FastAPI через REST API.

Основные экраны:
1. Регистрация и вход.
2. Главная страница с недавними приёмами пищи.
3. Food Tracker и дневная статистика.
4. Поиск и просмотр ресторанных блюд.
5. Страница блюда и генерация домашнего рецепта.
6. Редактор рецепта и выбор Budget / Standard / Premium.
7. Сравнение продуктов и расчёт стоимости.
8. Список покупок.
9. Профиль, предпочтения и ограничения.

Сначала реализовать основные сценарии и адаптивную вёрстку; мобильное приложение не входит в первую версию.

### Этап 6. Тестирование
1. Unit-тесты расчёта макронутриентов и стоимости.
2. Тесты фильтрации диетических ограничений.
3. Тесты API и прав доступа.
4. Тесты генерации/валидации AI-ответов с подменой внешнего API в автоматических тестах.
5. Проверить основные пользовательские сценарии вручную через Swagger и веб-интерфейс.

### Этап 7. Подготовить к деплою
1. Добавить Dockerfile приложения и production-конфигурацию.
2. Настроить GitHub Actions для тестов и проверок.
3. Выбрать среду развёртывания.
4. Настроить переменные окружения, HTTPS/SSL и Nginx, если он нужен выбранной инфраструктуре.
5. Развернуть backend и frontend.
6. Проверить логи, миграции, безопасность секретов и работу после перезапуска.

### Этап 8. Дополнительные возможности
1. Redis-кэширование там, где оно действительно полезно.
2. Celery для долгих фоновых задач.
3. pgvector/RAG для семантического поиска по каталогу, если он будет нужен.
4. Отдельный мобильный клиент после стабилизации веб-версии.

## 3. Подготовка проекта в Windows

Открой CMD в папке проекта.

```bat
py -3.12 --version
py -3.12 -m venv .venv
.venv\Scripts\activate
py -m pip install --upgrade pip
py -m pip install -r requirements.txt
copy .env.example .env
```

Заполни `.env`. Не добавляй настоящий `.env` в Git.

## 4. Запуск инфраструктуры

Убедись, что Docker Desktop запущен, затем выполни:

```bat
docker compose up -d
docker compose ps
```

PostgreSQL будет доступен на `localhost:5434`, Redis — на `localhost:6379`.

## 5. Запуск backend

После активации виртуального окружения:

```bat
py -m uvicorn app.main:app --reload
```

Открой Swagger: `http://127.0.0.1:8000/docs`

Проверка состояния: `http://127.0.0.1:8000/health`

## 6. Миграции базы данных

После добавления SQLAlchemy-моделей:

```bat
py -m alembic revision --autogenerate -m "initial schema"
py -m alembic upgrade head
```

Alembic уже имеет базовую конфигурацию в `migrations/env.py`. Перед применением проверь сгенерированный файл: Alembic не всегда может правильно определить намерение разработчика.

## 7. Тесты

```bat
py -m pytest
```

## 8. Переменные окружения

Смотри `.env.example`. Минимально нужны:
- `DATABASE_URL`
- `REDIS_URL`
- `SECRET_KEY`
- `OPENAI_API_KEY` (для AI-функций)

Ключи и пароли не вставляй в код, README или Git.

## 9. Текущий статус

Это стартовый каркас, а не готовое приложение. Alembic настроен базово; пока модели не созданы, миграция будет пустой. На первом этапе нужно проверить окружение, запустить API и инфраструктуру, затем согласовать схему данных и реализовать её поэтапно.
