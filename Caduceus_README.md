# Caduceus — последовательный план реализации

Caduceus — веб-приложение интеллектуального помощника по питанию. После завершения и стабилизации веб-версии можно создать мобильный клиент на том же backend.

## Согласованный функционал

1. **Food Tracker:** дневник питания, порции, калории, белки, жиры, углеводы, дневные итоги и история.
2. **Распознавание еды по фотографии:** загрузка изображения, анализ через OpenAI API, показ предполагаемого блюда/состава, ручное подтверждение и исправление перед добавлением в дневник.
3. **Restaurant Explorer:** поиск по собственному демонстрационному каталогу ресторанов и блюд.
4. **Recipe Builder:** генерация домашнего рецепта через OpenAI API, ингредиенты и количества, инструкция, время приготовления, порции и пищевая ценность.
5. **Замена ингредиентов:** предложения AI с последующей проверкой по каталогу и ограничениям пользователя.
6. **Dietary Preferences:** Vegan, Gluten-free, Dairy-free, Nut-free, High-protein, Budget-friendly и Low prep time. Для строгих аллергий неизвестный состав не считать безопасным.
7. **Smart Grocery:** режимы Budget / Standard / Premium, демонстрационные продукты/магазины/цены, расчёт стоимости использованного количества и стоимости целых упаковок, сравнение цен и список покупок.
8. **Пользовательский профиль:** регистрация, вход, JWT, собственные предпочтения, рецепты, дневник и списки покупок.

Каталоги ресторанов, блюд, ингредиентов, продуктов, магазинов и цены будут собственными демонстрационными данными в PostgreSQL. Реальных баз или внешних API магазинов/ресторанов у проекта нет.

## Текущий стек

- Python 3.12, FastAPI, Pydantic v2.
- PostgreSQL, SQLAlchemy 2, Alembic.
- JWT, хеширование паролей, Pytest.
- OpenAI API для рецептов, замен ингредиентов и анализа изображений.
- React + TypeScript для веб-интерфейса.
- Docker Compose; Redis и Celery для фоновых задач/кэширования.
- pgvector/RAG для семантического поиска по каталогу рецептов, блюд и ингредиентов.
- GitHub Actions, Nginx/SSL и выбранная облачная инфраструктура для деплоя.

# Порядок разработки

## Этап 1. Зафиксировать рабочее окружение — базово выполнено

**Задачи**
1. Проверить версию Python: `py -3.12 --version`.
2. Активировать `.venv`.
3. Установить зависимости: `py -m pip install -r requirements.txt`.
4. Проверить наличие локального `.env`, созданного из `.env.example`.
5. Запустить PostgreSQL и Redis через `docker compose up -d`.
6. Проверить контейнеры командой `docker compose ps`.
7. Запустить API командой `py -m uvicorn app.main:app --reload`.
8. Проверить `http://127.0.0.1:8000/health` и `http://127.0.0.1:8000/docs`.

**Результат:** локальное окружение запускается, контейнеры PostgreSQL и Redis работают, FastAPI отвечает.

## Этап 2. Настроить подключение к PostgreSQL

**Задачи**
1. Проверить `DATABASE_URL` в `.env`.
2. Подключить `app/db/session.py` к настройкам приложения.
3. Добавить зависимость FastAPI для выдачи и закрытия сессии БД.
4. Добавить тест проверки соединения с PostgreSQL.
5. Проверить подключение с помощью теста и короткой служебной проверки.

**Результат:** приложение может открывать и закрывать сессии PostgreSQL; база доступна из Python.

## Этап 3. Создать структуру базы данных

Создаём следующие сущности и связи.

| Таблица | Что хранит |
|---|---|
| `users` | email, хеш пароля, имя, дата создания |
| `dietary_preferences` | предпочтения, аллергии и строгие ограничения пользователя |
| `restaurants` | демонстрационные рестораны |
| `dishes` | блюда ресторана, описание, категория, изображение/ссылка при наличии |
| `ingredients` | ингредиенты и значения калорий, белков, жиров и углеводов на 100 г/мл |
| `dish_ingredients` | известные ингредиенты и количества для ресторанного блюда, если данные доступны |
| `recipes` | домашние рецепты, автор, исходное блюдо, количество порций, шаги и время |
| `recipe_ingredients` | ингредиенты, количество и единицы измерения в рецепте |
| `stores` | демонстрационные магазины |
| `products` | товары, связанный ингредиент, размер упаковки и единицы измерения |
| `product_prices` | товар, магазин, цена упаковки и дата/метка демонстрационных данных |
| `meal_entries` | пользователь, дата/время, приём пищи, блюдо/рецепт, порция и зафиксированные нутриенты |
| `shopping_lists` | пользователь, название списка и дата создания |
| `shopping_list_items` | список, товар/ингредиент, количество, отметка «куплено» |
| `food_scan_sessions` | пользователь, статус сканирования, результат AI, время и ссылка на временно сохранённое изображение при необходимости |
| `recipe_embeddings` | векторные представления объектов каталога для pgvector/RAG |

**Задачи**
1. Создать SQLAlchemy-модели в `app/models/`.
2. Описать первичные и внешние ключи, уникальные ограничения, индексы и связи.
3. Подключить все модели к `Base.metadata`.
4. Настроить Alembic на чтение `DATABASE_URL` и `Base.metadata`.
5. Создать первую миграцию: `py -m alembic revision --autogenerate -m "create initial schema"`.
6. Проверить файл миграции.
7. Применить миграцию: `py -m alembic upgrade head`.
8. Проверить созданные таблицы в PostgreSQL.

**Результат:** PostgreSQL содержит структуру всех основных данных приложения.

## Этап 7. Реализовать AI-генерацию домашних рецептов

**Задачи**
1. Создать отдельный `OpenAIService`, который читает ключ из `.env`.
2. Создать Pydantic-схему структурированного рецепта.
3. Реализовать endpoint создания домашнего рецепта из выбранного блюда.
4. Передавать AI только нужную информацию о блюде, ограничения пользователя и доступные ингредиенты.
5. Проверять ответ AI по Pydantic-схеме.
6. Проверять разумность количества порций, количеств и единиц измерения.
7. Сохранять подтверждённый рецепт и его ингредиенты в PostgreSQL.
8. Реализовать просмотр, редактирование и сохранение рецепта.
9. Добавить обработку тайм-аутов, ошибок API и некорректного ответа.
10. Написать тесты с mock-ответами AI, чтобы обычные тесты не расходовали API-кредиты.

**Результат:** по выбранному ресторанному блюду можно получить, проверить и сохранить домашний рецепт.

# Команды для ежедневной работы в Windows

## Активировать виртуальное окружение

```bat
.venv\Scripts\activate
```

## Запустить PostgreSQL и Redis

```bat
docker compose up -d
docker compose ps
```

## Запустить FastAPI

```bat
py -m uvicorn app.main:app --reload
```

## Открыть API

- Swagger: `http://127.0.0.1:8000/docs`
- Health check: `http://127.0.0.1:8000/health`

## Создать и применить миграции

```bat
py -m alembic revision --autogenerate -m "describe schema change"
py -m alembic upgrade head
```

## Запустить тесты

```bat
py -m pytest
```

## Текущий статус

- Локальное Python-окружение: подготовлено пользователем.
- PostgreSQL и Redis в Docker: запущены пользователем.
- FastAPI health endpoint: проверен пользователем.
- Следующий шаг: **Этап 2 — проверить/закрепить подключение FastAPI к PostgreSQL и тест соединения.**
